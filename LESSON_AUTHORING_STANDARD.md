# Current lesson-building standard

**Locked in by the teacher on 13 September 2026. Use this approach until the teacher changes it.** The teacher's instruction was: “Lock in these approaches to building lessons for now.” This fixes the authoring approach; it does not freeze every lesson into the same activity sequence.

## Teaching content

1. Give each lesson a clear title, specification-linked learning outcomes and a purposeful do now. Use retrieval, a prediction or a thinking task according to the learning need.
2. Teach the full demand of the mapped specification component. If the outcome says explain importance, pupils need the causal explanation and a task that elicits it; a definition and a spec code are insufficient. Identify partial coverage honestly.
3. Put the necessary information on the main teaching route in manageable steps. Include definitions, examples, comparisons, diagrams and modelled reasoning before pupils need them. A linked textbook or optional drawer is not a substitute for input.
4. Balance explanation with guided attempts, checks and substantial independent thinking. Use Rosenshine principles, visible-thinking routines and Bloom's categories where they serve the content. Do not force every routine or use the same task sequence for every lesson.
5. Make language easy, informative and directional. Say what pupils should do and what their explanation should connect. Pupils normally respond in books or on a designed resource.
6. Build adaptations around the actual barrier: precise support, a fresh attempt and reduced help when appropriate. Keep the destination ambitious for everyone. HOT should deepen reasoning through comparison, counterexamples, evaluation or transfer.

## Questions, answers and assessment

- **Every question-bearing slide and every pupil-response task must provide its model answer and mark scheme.** Include do nows, questions within input, guided/independent practice, hinges, calculations, extended responses, exits and task widgets.
- Keep answers hidden until an explicit “Model answer & mark scheme” control is opened. Retain the question beside the review. A new slide must not automatically expose its answer.
- Cover every subpart and match the current state of an interactive model. Give each HOT, adaptation, AI or UAE question its own relevant review rather than showing an unrelated main-slide answer.
- Marked questions need accurate totals, allocations, acceptable equivalents and important distinctions. Unmarked/open tasks need a defensible model and clearly labelled success criteria. Do not invent an exam-board mark scheme or fixed six-mark formula.
- Include suitable exam-style questions with command words and marks. Model how to develop a response, then provide independent application in a different context. Label original questions as original; distinguish them from sourced exam-board questions.
- Map each scored requirement to planned input, practice and a check before the assessment. Record actual delivery separately. A new context can be appropriate; untaught prerequisite knowledge cannot be silently assumed.
- Protect writing and review time. Rebalance or remove optional tasks when adding substantive content rather than pretending extra material takes no time.

## Presentation and widgets

Use the approved Arcadia Lesson Frame 1.0.0 visual approach with the teacher-requested answer-review controls demonstrated in the Year 10 Week 3 lessons. One projection surface; navy, warm paper and restrained gold; large readable type; thin full outlines; minimal outer margins. Keep the six screen families: Title, Learning outcome, Do now, Input, Assess and Thinking.

Learning outcomes open Resources alongside the task. Input, Assess and Thinking carry Resources, Assessments, Adaptation, HOT, AI literacy and UAE National Agenda. Populate widgets with purposeful lesson-specific content, real resources and exact screen destinations. AI and national-context tasks are available without being compulsory in every teaching sequence. Independent assessment screens can omit reference widgets while retaining the requested answer-review access.

Panels sit beside the question, preserve interaction state, and use their own tabs/pages. Page content before shrinking projected text or relying on scrolling. Preserve keyboard access, focus return and reduced-motion support.

Use scientifically accurate original diagrams, suitable interactive models or properly sourced/licensed images. Label schematic diagrams and illustrative data. A visual should explain a relationship or support reasoning. Local assets belong with each lesson so later template changes do not silently alter it.

## Files and publishing

- A direct lesson HTML entry point with its own local resource folder is the current package format. Everything does not have to be in one HTML file. Preserve the entry point and relative links when publishing.
- Keep pupil-facing model answers and mark schemes in the lesson's review controls. Keep confidential teacher notes, class information, teaching decisions and the private companion outside the public package.
- Keep a private teaching companion and a local source/build record. Record source provenance and permissions for images/libraries. Do not include pupil names, code-to-name keys, secrets or unrelated workspace files in a public publication.
- Publish only the selected lesson package and update the correct class and unit navigation. Check the configured destination rather than assuming a repository or branch. Preserve existing lesson URLs and earlier material.
- The teacher's explicit publication instruction authorises the requested push; do not ask for the same approval again. Check deployment completion and the live destination. Respect a session instruction to leave lesson tests to the teacher and record that honestly; a successful deployment does not constitute classroom or viewport QA.
